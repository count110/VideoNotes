# VideoNotes Feishu Relay

这是 VideoNotes Pro 的可选服务器端飞书命令中继。它不属于 macOS App
Bundle，也不会向 App 下发飞书 App Secret 或管理员令牌。

它的职责很小：在已经绑定的一台 Mac 与一个飞书群之间安全转发固定的复盘
指令。Mac 在本机生成复盘，再把结果通过 Relay 回复到原群消息。

## 能做什么

在完成一次性配对和群绑定后，授权管理员在目标群中 `@机器人` 后可发送：

- `帮助`
- `当前视频`
- `复盘当前视频`
- `复盘今天`

旧版 `当前视频复盘`、`今天复盘` 与 `发送当前复盘` 仍可用，以免已有群失效，
但机器人帮助不再显示它们。

每个飞书群只能绑定一台 VideoNotes。若需换设备，先在旧 Mac 的 VideoNotes
设置中执行“安全断开”，收到远程撤销确认后再配对新设备。

## 安全边界

- 使用飞书官方 Node SDK 的长连接，不开放事件回调公网端口。
- 只处理 `im.message.receive_v1` 的群 @ 机器人文本事件；事件 App ID、群类型、
  从飞书机器人身份接口取得的 Bot Open ID、mention Open ID 和绑定发起人均会再次校验。
- 必须是 `FEISHU_BINDER_OPEN_IDS` 中的人才能完成群绑定；绑定后同一群仅该人可发
  指令。
- 飞书 App Secret 只从进程环境变量读取，绝不能写入 Xcode、App、日志或仓库。
- Relay 的持久状态文件使用 AES-256-GCM 静态加密。文件中会保存配对与设备关联
  信息、设备令牌哈希、飞书群/绑定者/消息标识、命令状态，以及为失败重试保存的
  复盘回复正文；不会保存明文配对码或明文设备令牌。
- 这不是端到端加密：Relay 进程必须解密复盘正文后才能代机器人回复飞书。控制
  服务器和状态加密密钥的运营人员具有技术上访问这些数据的能力，因此服务器、
  密钥和备份必须由可信运营方管理。
- 配对码一次性、短时有效；同一安装 ID 与同一设备令牌的网络重试是幂等的。
- 命令、绑定、HTTP 配对入口都有保守的速率限制；公网 HTTPS 网关仍必须独立做
  防火墙、认证和限流。
- HTTP 服务只监听 loopback。生产部署请用认证后的 HTTPS 反向代理/隧道把必要
  的配对 API 安全暴露给用户设备；不要直接暴露此 Node 端口。

需要的飞书权限应保持最小化：

- `im:message.group_at_msg:readonly`
- 发送机器人回复所需的消息发送权限

请在飞书开发者后台启用“长连接”事件订阅和 `im.message.receive_v1`。

## 数据处理、保留与断开

Relay 只接收飞书投递给机器人的群 @ 消息事件，不拉取普通群消息或聊天历史。为了
验证绑定者并把结果回复到原消息，它仍会处理飞书群 ID、绑定者 Open ID、消息 ID、
命令文字/类型和时间；Open ID 是账号标识，不等同于读取成员资料。Mac 只向 Relay
提交最终复盘回复及执行状态，Relay 不接收本机完整笔记库或 DeepSeek API Key。

当前实现的清理规则如下。这里的“删除”是从活动状态文件中移除；若运营方另做备份，
还必须按其公开的备份保留政策处理副本。

| 数据 | 当前保留与清理行为 |
| --- | --- |
| 未领取的配对记录 | 配对码过期后，在下一次清理时删除 |
| 已领取但尚未完成群绑定的配对记录与设备 | 用于处理丢失的领取响应而短暂保留；在配置的 `RELAY_UNBOUND_CLAIM_TTL_SECONDS` 后（默认自领取起 1 小时）于下一次清理时一并删除。该值不得小于配对码有效期 |
| 已领取且完成群绑定的配对记录 | 只保存配对码哈希和关联信息；设备保持配对期间保留，成功“安全断开”时随该设备删除 |
| 设备与群绑定 | 保留到该设备成功执行“安全断开”或运营方撤销设备 |
| 未完成、过期或已撤销的命令 | 命令过期时间之后再保留 24 小时，然后在下一次清理时删除 |
| 已完成命令及复盘回复正文 | 正常连接期间，命令过期时间之后再保留 7 天，用于幂等、重启恢复和飞书发送失败重试；若设备先成功“安全断开”，活动状态中的回复正文会立即清除，只留下不含正文的命令元数据直到正常清理 |
| 已撤销设备的令牌哈希 | 保留 7 天，以识别安全断开的重复请求，然后在下一次清理时删除 |

清理在 Relay 启动或处理请求时执行，不是持续运行的精确定时器；如果服务停机，实际
删除会推迟到下一次启动或请求。不要向用户承诺已发送的飞书消息、运营方备份或全部
无正文元数据会随断开立即删除。

如果 Mac 在领取请求完成后、收到响应前退出或用户取消配对，Relay 不会收到这个取消
动作。上述未绑定领取时限会在下一次清理时移除这种孤立设备；在时限内，Mac 仍可用
同一配对码和本机令牌安全重试领取。

原配对码过期后，尚未完成群绑定的 Mac 会收到 `pairing_expired` 状态并提示使用新码
重新配对，不会持续显示“等待群绑定”。这个状态不影响此前丢失领取响应的同一请求重试。

用户在 VideoNotes 设置中选择“安全断开”时，Mac 会先请求 Relay 撤销设备。Relay
确认后会立即移除活动设备、群绑定和该设备的已领取配对记录，把尚未完成的命令标记为
已撤销，并清除所有已完成命令中保存的回复正文。尚未交给飞书的回复会取消发送且不再
重试；已经交给飞书的在途请求无法召回，已发送到群内的消息也不会由 Relay 自动删除。
Relay 仅继续保留 7 天撤销令牌哈希及按正常周期清理的不含正文命令元数据。Mac 随后
才会清除本地设备令牌和待发送结果。如果远程撤销没有得到确认，Mac 会停止继续接收
命令、保留凭据并提示重试，不能把失败显示成已断开。

## 安装与检查

要求 Node.js 20 或更高版本：

```bash
cd Relay
npm ci
npm run check
npm test
```

复制示例环境变量并仅在受控服务器上填写真实值：

```bash
cp .env.example .env
```

不要提交 `.env`，不要把 `FEISHU_APP_SECRET`、`RELAY_ADMIN_TOKEN` 或
`RELAY_STATE_ENCRYPTION_KEY` 给 macOS 客户端或群成员。

## 管理配对流程

Relay 启动后，可信运维端持有 `RELAY_ADMIN_TOKEN`，用它创建一次性配对码：

```bash
curl --fail-with-body \
  -X POST http://127.0.0.1:8787/v1/admin/pairing-codes \
  -H "Authorization: Bearer $RELAY_ADMIN_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{}'
```

把返回的 `code` 交给设备拥有者。用户在 VideoNotes 设置中填写 Relay HTTPS
地址和该码，Mac 会安全领取设备 ID 与本地令牌。随后由
`FEISHU_BINDER_OPEN_IDS` 中的管理员在目标群里 @机器人并发送：

```text
绑定 <配对码>
```

配对码只在群消息中由管理员使用；Relay 不会向群或日志回显该码。

## 客户端 API 摘要

所有设备请求均需 `Authorization: Bearer <device-token>`；管理员创建配对码使用
管理员令牌。不要将管理员令牌放入 VideoNotes。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `POST` | `/v1/admin/pairing-codes` | 仅运维端创建短时配对码 |
| `POST` | `/v1/pairing/claim` | Mac 用码、安全领取设备 |
| `GET` | `/v1/devices/:id` | 查询绑定状态 |
| `POST` | `/v1/devices/:id/heartbeat` | 心跳 |
| `GET` | `/v1/devices/:id/commands?wait_seconds=0..25` | 长轮询命令，空时 `204` |
| `GET` | `/v1/devices/:id/commands/:commandId` | 重启后查询命令结果 |
| `POST` | `/v1/devices/:id/commands/:commandId/result` | 回传一次复盘结果 |
| `DELETE` | `/v1/devices/:id` | 安全撤销设备；只有收到 `204` 后客户端才能清本地状态 |

`claim` 成功只返回 `device_id` 与 `binding_status`。客户端必须保留用户输入的
真实配对码，并在界面提示 `绑定 <该真实码>`；不要相信或显示任何服务器生成的
占位绑定文案。

## 启动

Node 本身不读取 `.env` 文件。请选择受控的进程管理器/密钥管理器把变量注入进程，
再运行：

```bash
npm start
```

启动后可访问本机 `GET /healthz` 检查长连接状态。飞书 SDK 会在短暂网络故障时自行
重连；在让用户配对前，运维人员应确认健康检查中的 `bot.connection` 为 `connected`。

## 生产部署提醒

1. 使用专用服务器账户、受限文件权限，并为加密状态文件备份制定且公开保留/删除周期。
2. 仅以 HTTPS 向可信客户端发布 Relay 地址，并让网关验证来源、限流和记录安全审计。
3. 轮换 App Secret、管理员令牌或状态加密密钥前先制定迁移/重新配对方案。
4. 不要在日志、截图、Issue、客服聊天或诊断包中放入设备令牌、配对码、AI 复盘正文。
5. 响应用户删除请求时，同时检查活动状态和仍在保留期内的备份；“安全断开”会清除
   活动状态中的配对记录与回复正文，但不等同于撤回飞书消息或删除全部备份与无正文元数据。
